# Generic Analytics Agent — Architecture

## Design principle

> **Every piece of domain knowledge is derived from data at ingestion time
> and stored in metadata tables. No file type, column name, language, or
> business term is hardcoded anywhere in the agent.**

---

## Metadata tables (DuckDB internal)

All domain knowledge lives here. Written at ingestion, read at query time.

| Table | What it stores |
|---|---|
| `_data_registry` | Loaded tables: name, source, row/col counts |
| `_column_catalog` | Per-column stats + inferred role (dimension / metric / yoy_delta / period / prior_period) |
| `_table_context` | Grain, period column, CY label, PY label, dimension/metric/yoy column lists, summary |
| `_semantic_map` | alias → canonical_col mappings in any language, generated by LLM |
| `_query_rules` | Table-specific SQL correctness rules, generated by LLM from data structure |
| `_relationships` | Cross-table join candidates detected by column name overlap + value overlap |

## Ingestion pipeline (`load_file`)

```
File (xlsx / csv / parquet / …)
        │
        ▼
1. Parse → DuckDB table
   - Auto-detects header row for messy Excel files (NIQ-style, with metadata rows)
   - Supports xlsx, csv, tsv, parquet out of the box
        │
        ▼
2. Statistical profiler
   - For every column: dtype, null rate, n_unique, min/max/mean/std, top-5 values
   - Assigns column_role via STATISTICAL SIGNATURES only:
       • period     → values match time-label patterns (regex on actual cell content)
       • yoy_delta  → numeric + name matches structural change-phrase + values near 0
       • prior_period → name matches prior-year structural phrase
       • dimension  → string + low cardinality ratio
       • metric     → numeric, remaining
   - Writes to _column_catalog
        │
        ▼
3. Grain inference
   - Reads actual period-column values
   - Matches against grain signatures (52W→annual, 4W→monthly, etc.)
   - Extracts CY and PY labels by date-score sorting (no date format assumptions)
   - Writes to _table_context
        │
        ▼
4. LLM semantic enrichment
   - Batched call: all column profiles → JSON
   - Returns per-column: description + 4-8 aliases in any language detected
   - Writes to _semantic_map
   - No domain strings passed into the prompt — only actual column names + sample values
        │
        ▼
5. LLM query rule generation
   - Passes table context (grain, cy_label, yoy_cols) to LLM
   - LLM derives rules from structure: e.g. "filter to CY when using yoy_delta cols"
   - Writes to _query_rules
        │
        ▼
6. Table summary
   - LLM generates plain-English summary of what the dataset contains
   - Stored in _table_context.summary
        │
        ▼
7. Relationship detection
   - Finds shared dimension column names across all loaded tables
   - Writes join candidates to _relationships
```

## Query pipeline (LangGraph)

```
User query
     │
     ▼
orchestrator_node
     │ classifies intent via LLM (seeded with live metadata)
     │
     ├─ structural intents (deterministic, format-agnostic):
     │   LOAD_FILE / META_QUERY / SCHEMA_LOOKUP /
     │   DISTINCT_VALUES / GRAIN_QUERY / SEMANTIC_LOOKUP
     │         │
     │         └─► final_answer (direct reply) ──► END
     │
     └─ ANALYTICS intent:
           │ resolves aliases against _semantic_map
           │ builds plan
           ▼
       sql_writer_node
           │ reads: _column_catalog, _table_context, _query_rules, _semantic_map
           │ injects all query rules into prompt at runtime
           ▼
       execute_sql_node  (deterministic, no LLM)
           ▼
       verifier_node
           │ reads: _query_rules, _table_context
           │ checks rule violations, missing filters, missing GROUP BY
           ├─ fail + corrected_sql → execute_sql_node (retry)
           └─ pass / warning
                 ▼
           final_answer_node
                 ▼
               END
```

## What makes it fully generic

### Column role detection
Driven entirely by statistical signatures and structural name patterns —
not by any domain vocabulary. The same detector correctly classifies:
- "%-Ver. Umsatz vs VJ" (German, NIQ MAT) as `yoy_delta`
- "Penetration (%) vs. VJ (% Ver.)" (German, NIQ Panel) as `yoy_delta`
- "Revenue YoY %" (English) as `yoy_delta`
- "Sales Δ vs Prior Year" (mixed) as `yoy_delta`

### Alias resolution
Pure retrieval from `_semantic_map`. The semantic map is built by the LLM
at ingestion by looking at actual column names and sample values — it detects
the language automatically and generates aliases in all relevant languages.

### Query rules
The Verifier has no hardcoded rules. It reads `_query_rules` at runtime.
These rules are generated by the LLM during ingestion based solely on the
table structure (which columns are yoy_delta, what the CY label is, etc.).

### Intent classification
The intent classifier uses the LLM, seeded with live metadata from the
loaded tables. It knows what columns exist because it reads `_column_catalog`
— not because anything is hardcoded.

### Period/grain inference
Works on any string format: "52 W bis 29/03/26", "Last 12M", "Q1 2025",
"Letzte 12 M VJ - 52 W bis 29/12/24". Regex patterns target structural
markers (numbers + time unit abbreviations), not fixed strings.

## Adding a new file

```bash
python main.py load data/my_new_file.xlsx my_table
```

That's it. The pipeline:
1. Finds the header row automatically
2. Profiles all columns statistically
3. Infers grain from period values
4. Generates aliases and descriptions via LLM (any language)
5. Generates query correctness rules from the data structure
6. Makes the table queryable in natural language immediately

No code changes. No config files. No manual mapping.

---

## Key design decisions

| Decision | Rationale |
|---|---|
| `_query_rules` as a table, not prompt strings | Rules are data. Adding a table never requires touching agent code. |
| LLM generates aliases at ingest, not query time | Aliases are persistent and auditable. Query time stays fast. |
| Column role via statistical signatures | Works for any language, any naming convention. |
| Grain inference via value parsing | Works for any period label format. |
| Intent classifier uses live metadata | Can detect adversarial queries ("no such column") without hardcoding. |
| Alias resolution is longest-first | Prevents short aliases matching inside longer compound terms. |
| Verifier reads rules from table | Correctness constraints are auditable and overridable without code changes. |
